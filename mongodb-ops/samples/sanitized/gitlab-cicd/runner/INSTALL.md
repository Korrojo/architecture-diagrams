# GitLab Runner Installation Baseline

This sample assumes a protected, project-scoped GitLab Runner using the
`shell` executor on RHEL 9 x86_64. The deployment Runner should execute one job
at a time.

## Capacity

For a host shared with another application, the current sample workload is
light. The practical minimum is:

| Resource | Minimum for this sample | Recommended operating rule |
|---|---:|---|
| CPU | 2 vCPU | Limit Runner jobs to approximately 1 vCPU |
| RAM | 8 GiB host total | Reserve at least 4 GiB for the existing application |
| Local disk | 20 GiB free | Keep builds/cache local; monitor `/opt` and `/var` |
| Concurrency | 1 deployment job | Do not run parallel deployment jobs |

A separate Runner host is preferable for production isolation. If the Runner
must share a host, the Linux and application teams must approve co-location,
resource limits, and capacity reservations based on measured utilization.

## Required Software

- GitLab Runner for RHEL 9 x86_64
- Git
- Bash
- Python 3.11 or newer, `pip`, and `venv`
- AWS CLI v2
- MongoDB Shell (`mongosh`) for operational troubleshooting
- `curl`, `jq`, `ca-certificates`, `openssl`, `tar`, `gzip`, and `unzip`
- Organization root/intermediate CA certificates for GitLab, Ops Manager,
  MongoDB, AWS endpoints, and the internal Python package repository

Java and Maven are **not required**. Python performs both changes in this
sample. Install Java only for a separate Java build or Java-based migration
tool.

The Python packages in `requirements.txt` must be available from the approved
internal Python repository. Configure the Runner user's `pip.conf`; do not
commit repository credentials.

## Service Account and Filesystem

Run the service as the dedicated `gitlab-runner` OS account. Create writable
directories owned only by that account:

```bash
sudo install -d -o gitlab-runner -g gitlab-runner -m 0750 \
  /opt/gitlab-runner/builds /opt/gitlab-runner/cache
```

Do not add the account to privileged groups and do not grant passwordless sudo.
The shell executor runs repository code directly on the host.

## Registration

Create a project Runner in GitLab, then register it using the one-time
authentication token displayed by GitLab:

```bash
sudo gitlab-runner register \
  --non-interactive \
  --url "https://gitlab.example.invalid" \
  --token "<one-time-runner-authentication-token>" \
  --executor "shell" \
  --description "mongodb-deploy-rhel9" \
  --tag-list "mongodb-deploy" \
  --run-untagged="false" \
  --locked="true"
```

In GitLab, mark this Runner **Protected** and keep it locked to the project.
Never store the Runner authentication token in the repository.

Use `config.toml.example` as a review guide, not as a replacement for the file
generated by registration. Set `concurrent = 1`.

## Service Limits

Copy the reviewed systemd override and reload:

```bash
sudo install -d -m 0755 /etc/systemd/system/gitlab-runner.service.d
sudo cp runner/gitlab-runner.service-override.conf.example \
  /etc/systemd/system/gitlab-runner.service.d/override.conf
sudo systemctl daemon-reload
sudo systemctl enable --now gitlab-runner
sudo systemctl status gitlab-runner
```

The example caps the Runner service and its shell-job child processes. Adjust
only after measuring the existing application workload.

## AWS Identity and Network

Attach an EC2 instance profile based on
`infrastructure/iam/runner-policy.json`. The Runner should not store static AWS
access keys.

Permit outbound HTTPS to:

- The GitLab instance
- Approved Python/RPM package repositories
- AWS Systems Manager, Secrets Manager, KMS, and STS endpoints, or VPC endpoints
- Ops Manager
- MongoDB deployment endpoints

Permit DNS resolution and time synchronization. The Runner needs TCP access to
MongoDB and HTTPS access to Ops Manager; it does not need inbound Internet
access.

## Validation

Run these checks as the `gitlab-runner` account:

```bash
sudo -u gitlab-runner git --version
sudo -u gitlab-runner python3 --version
sudo -u gitlab-runner aws sts get-caller-identity
sudo -u gitlab-runner gitlab-runner verify
sudo systemctl is-active gitlab-runner
```
